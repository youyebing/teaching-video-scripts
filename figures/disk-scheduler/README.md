# 寻道顺序试验台 · Seek order test stand

《磁盘调度教学视频脚本.md》的配套图解装置。不是示意图，是一台能运转的等距仪器：
转盘负责「旋转」，桥架滑架负责「移臂」，卡架负责「排队」，表盘负责「记行程账」。

- 页面：`disk-scheduler.html`（深色）/ `disk-scheduler-light.html`（浅色，推荐录屏用这个）
- 模型：`model.mjs`（纯数据，页面里每个数字都来自它）
- 构建：`node build.mjs`（加深色）/ `node build.mjs --light` / `node build.mjs --audit`
- 出视频：见本文末「录制」

## 这台机器怎么对应脚本

| 机器上的东西 | 对应考纲概念 | 用在哪一幕 |
|---|---|---|
| 卡架里九张请求卡（①～⑨） | 进程请求序列（柱面/磁头/扇区） | P4 手推真题 |
| 卡架上方的读数头，跳到哪张卡 | 下一个服务谁＝调度顺序 | P3、P4 |
| 被服务过的卡抬起来 | 已完成的请求 | P4 走完一遍 |
| 转盘 + 盘面 12 圈轨道 | 柱面（一圈一条柱面） | P2 先移臂后旋转 |
| 转盘匀速转、亮着的扇区标线转到读头下 | 旋转延迟：要等的扇区转过来 | P2、P3 |
| 桥架滑架沿半径进出 | 移臂调度（寻道） | P2、P3 |
| 表盘指针 | 累计移臂行程（格） | P3 比 26 / 8 / 16 |
| 三档旋钮 | FCFS / SSTF / SCAN | P3 |

## 真值表（由 `model.mjs` 算出，页面读的就是这套数）

题源：2022 年下半年系统架构设计师上午卷第（4）题；起点 20 号柱面。

| 算法 | 响应序列 | 移臂总行程 |
|---|---|---|
| FCFS 先来先服务 | ①②③④⑤⑥⑦⑧⑨ | **26 格**（来回甩） |
| SSTF 最短寻道优先 | **④⑥⑨⑤⑦①②⑧③**（＝真题答案 C） | **8 格** |
| SCAN 电梯 | ④⑥⑨⑤⑦①②⑧③（末段空驶到 26 再折返） | **16 格** |

SSTF 序列与真题答案 C 一致；同柱面内按扇区升序、同扇区按磁头升序（①⑦ 同为 18 柱面扇区 6，⑦ 的磁头 7 在 ① 的磁头 8 前）。

SCAN 的序列与 SSTF 相同，行程却多一倍——多出来的正是 22 → 26 那段没有请求的空驶。
这正是电梯算法的代价，也是「不饿死人」买来的东西。

## 交互

- 点图 / 按 `1` `2` `3`：切换 FCFS、SSTF、SCAN
- 空格：暂停 · `r`：重来
- 无操作时自动轮播三种算法（每轮走完自动换下一种）

## 怎么出片（带旁白，音画逐拍对齐）

片子不是"录屏"，是**逐拍编排**：每一张请求卡是一拍，那一拍的画面长度 = 那一拍的语音长度 + 呼吸，
画面内容是仿真里这一拍的时间区间被拉伸到这段长度。所以话长画就慢，图和话不会错位。

四步：

```sh
# 1) 旁白：文本在 audio/manifest.json 里，逐拍合成（本机语音，中文女声 Tingting）
#    say -v Tingting -r 160 -o /tmp/x.aiff "……" && ffmpeg -i /tmp/x.aiff -ar 44100 -ac 1 audio/<mode>-<i>-<beat>.wav
#    （wav 不进 git，随用随生成；文本才是资产）

# 2) 分镜 + 出帧动作表：把语音长度、仿真拍区间、帧号算成 plan.json 和动作表
python3 plan_video.py          # 打印：拍数 / 总时长 / 需出帧数

# 3) 出帧（anatomy 技能里的 drive.mjs）
node <anatomy>/scripts/drive.mjs disk-scheduler-light.html \
  --actions /tmp/actions.json --height 900 --scale 2

# 4) 编码：每拍单独编码（运动拍用帧序列、静帧拍用单帧循环）→ 拼画面 → 拼"语音+补齐静音" → 合流
python3 encode_video.py
```

产出：`磁盘调度-试验台演示（带旁白）.mp4`，3 分 05 秒，1316×932 / 20fps / AAC 单声道。

**重出成片的时间账**：出帧实测 0.16–0.33 秒/张（`--scale 2`，同一台机器不同轮次差别不小），2377 张约 6–13 分钟；
把 `--scale` 降到 1 或 FPS 降到 15 可以减半。编码约 1 分钟。

### 这一版的分镜时间轴

| 时间 | 内容 |
|---|---|
| 0:00–0:50 | FCFS：九拍拍完，表盘 26 格；收尾讲"路绕不是活多" |
| 0:50–1:56 | SSTF：按最近原则重排成 ④⑥⑨⑤⑦①②⑧③，表盘 8 格 |
| 1:56–3:05 | SCAN：做到 22 后空驶到 26 才折返，表盘 16 格；收尾讲饥饿与等待上限 |

调整节奏只需改两处：`plan_video.py` 里的 `HOLD_PAD`（每拍呼吸）与 `HOLD_MIN`（最短拍长）；
要改配音就改 `audio/manifest.json` 里的文本再重跑 1–4 步。

- `node scripts/lines.mjs` → **line ends: 0**（301 个线端全部落在笔画/点/轮廓上），静态与按 1/2/3 切换后的动态状态都测过

- 4 倍放大核对：读头滑块、卡架铣槽、表盘刻度、柱脚与横梁接合处

## 已知取舍

- 盘面轨道画了 12 圈（柱面 14–26），到 4 倍放大会看见圈距很密：这是台架，不是真盘，圈距按行程均分，不按真实磁道密度。
- 扇区标线固定 10 个（对应考题里扇区号 1–10），不随请求数变。
- SCAN 走到柱面 26（本台架的行程外端）才折返——教材里的「扫描算法」就是走到盘的一端，这里把「盘的一端」定在 26。

## 踩坑记录（下次做解剖图直接用）

1. **移动件必须同时有两套坐标**：几何按局部原点建、静态图上用 `translateAlong(P, 世界偏移)` 落到静止位置，审计记录的形状要用 `A.moved(shape, 世界偏移)`。只做其中一半的后果是：静态图里部件堆在原点，`--audit` 会报出一堆莫名其妙的深度环。
2. **一个条目只能有一个深度**：横跨前后的部件（卡架的背挡条与前挡条、桥架的柱与横梁、横穿导轨的支臂）必须拆成独立条目，否则审计报 `cycle`——这不是打包偏心能修的，是几何上真的前后都有。
3. **实测不到的判据要换形状**：一开始把「扇区到位」写成「偏离 < 0.09 持续 0.22 秒」，盘片 3 rad/s 时这个窗口只有 60 ms，永远判不到；改成穿越检测（`was > now`）才动得起来。
4. **逐帧出图要独占时钟**：页面的 rAF 循环与 `__seek(t)` 会同时推进同一个仿真，动画会快好几倍。确定性模式里必须 `cancelAnimationFrame(frame)` 并把 `tick` 变成空转。
5. **线要落在东西上**：扇形标线从轮毂边缘画到盘片外缘轮廓（不是留 2.5 单位悬浮），旋钮指针从轮毂环起画——`scripts/lines.mjs` 对静态和动态都要跑到 0。
6. **一轮出图只能有一个写手**：并行跑两个录屏任务写同一个 `frames/` 和同一份日志，后一轮的 `rm -rf frames` 会把前一轮的帧删掉、日志互相覆盖，最坏情况是编码进混合内容。改模型就重跑，别为了省 7 分钟并行跑；要并行就各自用独立目录（`frames-a/`、`frames-b/`）并在编码前核对帧数与首末帧读数。
